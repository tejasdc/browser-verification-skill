# Native updates must preserve every open tab

A click guard proves only the tab that owns the button. A PWA library can reload all
controlled tabs when one tab accepts a waiting worker. Test the actual native update:
serve two asset trees on one owned origin, invoke the browser registration's update
check, observe installed/waiting/activated states, then accept through the real UI.
Keep an unsaved draft in a second tab and assert both exact text and unchanged document
time origin. Use the library's documented reload interception seam when it exists;
do not simulate update events or replace its worker/activation protocol.

When discovery itself is the requested behavior, publish the second asset tree and
trigger the application's launch, foreground, reconnect, timer or manual-check path.
Do not call `registration.update()` from that test: it bypasses the missing behavior
while still proving the native lifecycle works. Install a virtual clock before the app
creates its timers, as described in `playwright-setup.md`. Verify actual waiting-worker
and cached-asset identity, unchanged document identity before acceptance, initial
registration/check failure recovery, and dismissal surviving repeated checks. Evidence:
Thinkering update-discovery acceptance, 2026-09-10; direct update calls in the existing
draft tests could not establish automatic discovery or Settings recovery.

Record cached response content hashes and loaded module URLs. An update label, worker
script URL or a successful page reload alone does not establish which revision ran.
If normal CI has one build, two HTML revisions generated by the actual Workbox/VitePWA
configuration can prove native lifecycle and data preservation. Disclose that scope:
they do not prove compatibility between different application bundles or data schemas.
Use explicit read-only old/new asset trees for that acceptance. A historical source with
a backported guard is a controlled fixture, not a previously deployed guarded release.

After another tab activates the new worker, open a previously unopened lazy workspace
in the retained old tab. Its old module URL may be absent from the new manifest and
server. Check actual module MIME type and rendered interaction, not status200: an SPA
fallback can return HTML for missing JavaScript while a framework error boundary catches
the failure before `pageerror`. Normal Chromium HTTP-cache success does not establish
that WebKit can fetch the same old module. Preserve the failure and fix the responsible
serving or lifecycle boundary rather than disabling error assertions.

Workbox `PrecacheController.activate` removes entries absent from the new precache
manifest. The separate `cleanupOutdatedCaches` option concerns incompatible older
Workbox caches; disabling it does not disable that entry cleanup. Inspect locked native
source before proposing a cache flag as a repair.

Prove persistence independently: acknowledge actual local writes while replication is
unavailable, preserve their exact archive through the update/reload, then enable actual
replication and inspect the server after reopening its database. A local render is not
proof that the server has the same bytes. Keep fixtures synthetic and origins/data owned.

Evidence: Thinkering native acceptance, 2026-09-07. Pristine55 lost a second tab's unsaved
capture on another tab's update; public vite-plugin-pwa `onNeedReload` preserved it.
Different actual bundles then passed Chromium but failed Linux WebKit on an unopened
old hashed Agents module, which returned200 HTML and hit React's error boundary.
The native same-code revision control passed both engines with exact local/SQLite records.
